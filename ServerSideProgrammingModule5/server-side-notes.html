Introduction to Server-Side Programming
Client-side code runs in the browser. Server-side code runs on a remote computer (the server) and sends results back to the browser. The server handles business logic, database access, authentication, and file operations — things the browser cannot or should not do.
What client-side CANNOT do
  • ✗ Access databases directly (SQL, MongoDB)
  • ✗ Read/write files on the server
  • ✗ Keep secrets (API keys, passwords) hidden
  • ✗ Send emails, SMS, push notifications
  • ✗ Handle authentication securely
  • ✗ Process payments (Razorpay, Stripe)
What server-side does
  • ✓ Receives HTTP requests from browser
  • ✓ Queries databases and returns data
  • ✓ Validates and processes form data
  • ✓ Authenticates users (login, JWT, sessions)
  • ✓ Calls third-party APIs with secret keys
  • ✓ Returns HTML pages or JSON data

Key concept — Dynamic vs Static: A static website serves the same HTML file to every user (like S3 hosting). A dynamic website runs server-side code that generates different responses based on who is asking, what data is in the database, and what time it is.

Server-side Language
Node.js
Node.js is a JavaScript runtime built on Chrome's V8 engine. It lets you run JavaScript on the server — the same language you use in the browser. Non-blocking I/O makes it extremely fast for handling many concurrent requests.
Node.js
Created by Ryan Dahl · 2009 · JavaScript runtime · V8 engine
Non-blocking I/O
Key features
  • → Same language (JS) on front and back end
  • → Event-driven, non-blocking I/O model
  • → NPM — world's largest package registry
  • → Express.js — minimal web framework
  • → Perfect for REST APIs and real-time apps
  • → Used by Netflix, PayPal, LinkedIn, NASA
Non-blocking explained
Traditional servers (PHP/Apache) create one thread per request — 1000 users = 1000 threads, high memory.

Node.js uses one thread + event loop. While waiting for DB response, it handles other requests. 1000 users = 1 thread, low memory.
server.js — Node.js + Express REST API for Students
// Step 1: install → npm install express
const express = require('express');
const app     = express();
app.use(express.json());   // parse JSON request bodies

// In-memory data (replace with database later)
let students = [
  { id: 1, name: 'Arjun', gpa: 8.7, course: 'MCA' },
  { id: 2, name: 'Priya', gpa: 9.1, course: 'MCA' },
];
let nextId = 3;

// GET all students → curl http://localhost:3000/students
app.get('/students', (req, res) => {
  res.json(students);
});

// GET one student by id → /students/1
app.get('/students/:id', (req, res) => {
  const student = students.find(s => s.id == req.params.id);
  if (!student) return res.status(404).json({ error: 'Not found' });
  res.json(student);
});

// POST add new student → body: { name, gpa, course }
app.post('/students', (req, res) => {
  const { name, gpa, course } = req.body;
  if (!name) return res.status(400).json({ error: 'Name required' });
  const newStudent = { id: nextId++, name, gpa, course };
  students.push(newStudent);
  res.status(201).json(newStudent);   // 201 = Created
});

// PUT update student
app.put('/students/:id', (req, res) => {
  const index = students.findIndex(s => s.id == req.params.id);
  if (index === -1) return res.status(404).json({ error: 'Not found' });
  students[index] = { ...students[index], ...req.body };
  res.json(students[index]);
});

// DELETE student
app.delete('/students/:id', (req, res) => {
  students = students.filter(s => s.id != req.params.id);
  res.status(204).send();  // 204 = No Content
});

app.listen(3000, () => console.log('Server running on port 3000'));

students.php — PHP REST API with MySQL
<?php
// Set response header to JSON
header('Content-Type: application/json');
header('Access-Control-Allow-Origin: *');  // allow CORS

// Connect to MySQL database
$conn = new mysqli('localhost', 'root', '', 'vtu_db');
if ($conn->connect_error) {
    http_response_code(500);
    echo json_encode(['error' => 'DB connection failed']);
    exit;
}

// Route by HTTP method
$method = $_SERVER['REQUEST_METHOD'];

switch ($method) {

    case 'GET':
        // GET /students.php?id=1 → one student
        if (isset($_GET['id'])) {
            $id   = (int)$_GET['id'];   // cast to int prevents SQL injection
            $result = $conn->query("SELECT * FROM students WHERE id=$id");
            echo json_encode($result->fetch_assoc());
        } else {
            // GET /students.php → all students
            $result = $conn->query("SELECT * FROM students");
            $rows = [];
            while ($row = $result->fetch_assoc()) $rows[] = $row;
            echo json_encode($rows);
        }
        break;

    case 'POST':
        // POST with JSON body
        $data = json_decode(file_get_contents('php://input'), true);
        $name = $conn->real_escape_string($data['name']);
        $gpa  = (float)$data['gpa'];
        $conn->query("INSERT INTO students(name,gpa) VALUES('$name',$gpa)");
        http_response_code(201);
        echo json_encode(['id' => $conn->insert_id]);
        break;

    case 'DELETE':
        $id = (int)$_GET['id'];
        $conn->query("DELETE FROM students WHERE id=$id");
        http_response_code(204);
        break;
}
$conn->close();
?>

app.py — Python Flask REST API
# pip install flask
from flask import Flask, jsonify, request

app = Flask(__name__)

# In-memory data
students = [
    { 'id': 1, 'name': 'Arjun', 'gpa': 8.7, 'course': 'MCA' },
    { 'id': 2, 'name': 'Priya', 'gpa': 9.1, 'course': 'MCA' },
]
next_id = 3

# @app.route decorator maps URL + method to a function

@app.route('/students', methods=['GET'])
def get_students():
    return jsonify(students)   # converts list to JSON response

@app.route('/students/<int:id>', methods=['GET'])
def get_student(id):
    student = next((s for s in students if s['id'] == id), None)
    if not student:
        return jsonify({'error': 'Not found'}), 404
    return jsonify(student)

@app.route('/students', methods=['POST'])
def add_student():
    global next_id
    data = request.get_json()          # parse JSON body
    if not data.get('name'):
        return jsonify({'error': 'Name required'}), 400
    new_student = {
        'id'    : next_id,
        'name'  : data['name'],
        'gpa'   : data.get('gpa', 0),
        'course': data.get('course', 'MCA')
    }
    students.append(new_student)
    next_id += 1
    return jsonify(new_student), 201   # 201 = Created

@app.route('/students/<int:id>', methods=['DELETE'])
def delete_student(id):
    global students
    students = [s for s in students if s['id'] != id]
    return '', 204

if __name__ == '__main__':
    app.run(debug=True, port=5000)

VTU Exam tip: The key difference is the execution model. Node.js is non-blocking — it handles thousands of concurrent requests on one thread. PHP and Python (Flask) are synchronous — each request waits for the previous one to complete. This makes Node.js better for real-time apps like chat, live dashboards, and multiplayer games.

Web Services
RESTful Web Services & APIs
REST (Representational State Transfer) is an architectural style for building web APIs. A RESTful API lets different applications communicate over HTTP using standard methods — GET, POST, PUT, DELETE — and exchange data in JSON format.
6 REST Constraints (Roy Fielding, 2000)
  1. 1.Client-Server — UI and data storage are separated
  2. 2.Stateless — each request contains all info needed. Server stores no session.
  3. 3.Cacheable — responses can be cached by client
  4. 4.Uniform Interface — consistent URL structure and methods
  5. 5.Layered System — client doesn't know if it talks to server or proxy
  6. 6.Code on Demand — optional: server can send executable code
HTTP Methods → CRUD mapping

Calling a REST API from AngularJS using $http
// AngularJS — calling the Node.js / PHP / Python REST API
app.controller('StudentCtrl', function($scope, $http) {

  // GET — fetch all students from server
  $http.get('http://localhost:3000/students')
    .then(function(response) {
      $scope.students = response.data;   // parsed JSON array
    })
    .catch(function(error) {
      $scope.errorMsg = 'Failed to load students';
    });

  // POST — add new student to server
  $scope.addStudent = function() {
    $http.post('http://localhost:3000/students', $scope.newStudent)
      .then(function(response) {
        $scope.students.push(response.data);  // add to UI list
        $scope.newStudent = {};                 // clear form
      });
  };

  // DELETE — remove a student
  $scope.remove = function(id) {
    $http.delete('http://localhost:3000/students/' + id)
      .then(function() {
        $scope.students = $scope.students.filter(s => s.id !== id);
      });
  };
});

SQL Databases — Relational
SQL databases store data in tables with rows and columns — like a structured spreadsheet. Relationships between tables are defined using primary keys and foreign keys. MySQL, PostgreSQL, SQLite, and Microsoft SQL Server are all relational databases.

students.sql — Create, Insert, Query, Join
-- Create the students table
CREATE TABLE students (
  id      INT PRIMARY KEY AUTO_INCREMENT,
  name    VARCHAR(100) NOT NULL,
  roll    VARCHAR(20)  UNIQUE NOT NULL,
  gpa     DECIMAL(3,1) DEFAULT 0.0,
  course  VARCHAR(50),
  created_at DATETIME DEFAULT NOW()
);

-- Insert rows
INSERT INTO students (name, roll, gpa, course) VALUES
  ('Arjun Sharma', '4MCA001', 8.7, 'MCA'),
  ('Priya Nair',   '4MCA002', 9.1, 'MCA'),
  ('Ravi Kumar',   '4MCA003', 7.5, 'MCA');

-- SELECT all
SELECT * FROM students;

-- SELECT with WHERE condition
SELECT name, gpa FROM students WHERE gpa >= 8.0;

-- SELECT with ORDER BY and LIMIT
SELECT * FROM students ORDER BY gpa DESC LIMIT 3;

-- UPDATE a row
UPDATE students SET gpa = 9.2 WHERE id = 1;

-- DELETE a row
DELETE FROM students WHERE id = 3;

-- Aggregate functions
SELECT
  COUNT(*) AS total,
  AVG(gpa) AS avg_gpa,
  MAX(gpa) AS highest,
  MIN(gpa) AS lowest
FROM students;

-- JOIN — link students to a courses table
CREATE TABLE courses (
  id   INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(100),
  student_id INT,
  FOREIGN KEY (student_id) REFERENCES students(id)
);

SELECT s.name, s.gpa, c.name AS course_name
FROM students s
JOIN courses c ON s.id = c.student_id;

NoSQL Databases — Non-Relational
NoSQL databases store data without fixed schemas — as documents, key-value pairs, graphs, or wide columns. MongoDB is the most popular NoSQL database, storing data as JSON-like documents. No tables, no rows, no JOINs.
Types of NoSQL databases
TypeDatabaseUse case
DocumentMongoDB, FirestoreJSON-like records, flexible schema
Key-ValueRedis, DynamoDBSessions, caching, fast lookups
GraphNeo4jSocial networks, recommendations
Wide ColumnCassandraTime series, IoT data, analytics
SQL vs NoSQL — when to use which
SQL (MySQL)NoSQL (MongoDB)
Fixed schema (columns defined)Flexible schema (add fields anytime)
Strong relationships (JOINs)Embedded documents, no JOINs
ACID transactionsEventual consistency
Banking, ERP, HR systemsCatalogs, social, real-time apps
Structured, stable dataVariable, rapidly changing data
mongo.js — MongoDB with Node.js (Mongoose ODM)
// npm install mongoose
const mongoose = require('mongoose');

// Connect to MongoDB
mongoose.connect('mongodb://localhost:27017/vtu_db');

// Define a Schema — structure of each document
const studentSchema = new mongoose.Schema({
  name   : { type: String, required: true },
  roll   : { type: String, unique: true },
  gpa    : { type: Number, min: 0, max: 10 },
  course : { type: String, default: 'MCA' },
  createdAt: { type: Date, default: Date.now }
});

// Create a Model from the Schema
const Student = mongoose.model('Student', studentSchema);

// CREATE — insert a document
const arjun = new Student({ name: 'Arjun', roll: '4MCA001', gpa: 8.7 });
await arjun.save();

// READ all documents
const allStudents = await Student.find();

// READ with filter — gpa >= 8
const topStudents = await Student.find({ gpa: { $gte: 8 } });

// READ one by id
const one = await Student.findById('64abc123...');

// UPDATE — set gpa to 9.0 where name is Arjun
await Student.updateOne({ name: 'Arjun' }, { gpa: 9.0 });

// DELETE one document
await Student.deleteOne({ roll: '4MCA001' });

// MongoDB query operators:
// $gte = >=    $lte = <=    $ne = !=
// $in = in array    $regex = pattern match
Student.find({ course: { $in: ['MCA', 'BCA'] } });
Student.find({ name: { $regex: /^A/i } }); // names starting with A
MongoDB document example — the student object looks exactly like JSON:

{ "_id": "64abc123...", "name": "Arjun", "roll": "4MCA001", "gpa": 8.7, "course": "MCA", "createdAt": "2024-01-15T..." }

No table structure required. You can add a city field to some documents and not others — SQL would require an ALTER TABLE for this.

Quick Reference — Server-Side & REST
Node.jsJavaScript on the server. Non-blocking event loop. npm for packages. Express.js for web APIs. Best for REST APIs and real-time apps.
PHPRuns inside HTML with <?php ?>. Synchronous. Easy MySQL integration. Powers 77% of server-side web. Laravel is the main framework.
Python (Flask)@app.route() decorator maps URLs to functions. jsonify() returns JSON. pip for packages. Django is the full-featured alternative.
RESTStateless HTTP API using GET/POST/PUT/DELETE. JSON responses. URLs are nouns (resources), methods are verbs. Defined by Roy Fielding 2000.
Status codes200=OK, 201=Created, 204=No Content, 400=Bad Request, 401=Unauthorized, 403=Forbidden, 404=Not Found, 500=Server Error.
SQLTables with fixed schema. PRIMARY KEY, FOREIGN KEY. SELECT/INSERT/UPDATE/DELETE. JOIN combines tables. MySQL, PostgreSQL, SQLite.
MongoDBDocuments (JSON-like). No fixed schema. find(), save(), updateOne(), deleteOne(). Mongoose adds schema validation in Node.js.
Non-blocking I/ONode.js handles multiple requests on one thread. While waiting for DB response, it processes other requests. Uses event loop + callbacks/promises.
SQL vs NoSQLSQL: fixed schema, JOINs, ACID, banking/ERP. NoSQL: flexible schema, no JOINs, scalable, social/real-time apps. Not either/or — many apps use both.
