01
Foundation
Why Do Front-End Frameworks Exist?
As web applications became more complex, plain HTML + CSS + JavaScript became difficult to organise and maintain. Frameworks solve structural problems that arise at scale.
🔴 Problems without a framework
  • ✗DOM spaghetti — getElementById and innerHTML scattered across thousands of lines
  • ✗State management — keeping UI in sync with data manually causes bugs
  • ✗No reusability — copy-pasting HTML blocks instead of components
  • ✗Full page reloads — every user action requires a server round-trip
  • ✗No routing — multi-page navigation requires separate HTML files
  • ✗Team scaling — no conventions mean every developer writes differently
🟢 What frameworks provide
  • ✓Component model — reusable, self-contained UI pieces with their own HTML, CSS, and JS
  • ✓Reactive data binding — UI automatically updates when data changes
  • ✓Single Page Apps (SPA) — page never reloads; router changes views in-browser
  • ✓Virtual DOM / Change Detection — efficient, minimal DOM updates
  • ✓Conventions & structure — enforces consistent code organisation across a team
  • ✓Ecosystem — routing, state management, testing, devtools all included or available
📊 The Core Concept — Component-Based Architecture
Every modern front-end framework is built around the idea that a UI is a tree of components. Each component manages its own state and renders its own HTML. When data changes, only that component re-renders — not the whole page.
App (root)
  ├── Navbar component
  ├── Dashboard component
  │    ├── StatsCard component ← has its own state: { value: 42 }
  │    ├── Chart component
  │    └── StudentList component
  │         └── StudentRow × N ← reusable, one per student
  └── Footer component
Key definition — Single Page Application (SPA): A web app that loads one HTML page and dynamically updates content using JavaScript instead of loading new pages from the server. Gmail, Twitter, and Google Maps are SPAs. Front-end frameworks are the primary tool for building SPAs.
02
History
Evolution of Front-End Frameworks
The progression from static HTML → jQuery → MVC frameworks → component-based architecture over two decades.
1995–2005 — The Static Era
HTML + plain JavaScript

Web pages were mostly static documents. JavaScript was used for simple effects. Every action required a full page reload from the server.

2006 — jQuery
DOM manipulation library

jQuery standardised cross-browser DOM access with $(selector). It solved browser inconsistency but was still procedural — no structure, no components, callback hell at scale.

2010 — AngularJS (Angular 1)
First major MVC framework — Google

AngularJS introduced two-way data binding, directives, controllers, and dependency injection to the browser. It brought server-side MVC patterns to the front end. Widely adopted in enterprise applications.

2013 — React
Component library — Facebook/Meta

React introduced the Virtual DOM and JSX. It was intentionally a UI library only (not a full framework), letting developers choose their own tools for routing and state. Became the most popular choice by 2016.

2014 — Vue.js
Progressive framework — Evan You

Created by an ex-Googler who combined the best ideas from AngularJS and React. Vue is progressive — you can use just the core view layer, or adopt the full ecosystem gradually.

2016 — Angular 2+ (TypeScript)
Complete rewrite — Google

Angular was completely rewritten from scratch in TypeScript. Note: AngularJS = Angular 1 (JavaScript). Angular = Angular 2+ (TypeScript). They are different frameworks despite the name.

2019–Present — Svelte, Next.js, Nuxt
Meta-frameworks and compile-time approaches

Next.js (React-based) and Nuxt (Vue-based) added server-side rendering. Svelte moved framework work to compile time — zero runtime framework overhead. The ecosystem continues to evolve rapidly.

Framework Overview
React — UI Library by Meta
⚛
React
Created by Jordan Walke at Facebook (2013)  ·  Maintained by Meta Library (not a full framework) Most popular · 2024

React is technically a UI library, not a full framework — it handles only the View layer. You choose your own routing (React Router), state management (Redux, Zustand), and other tools. This flexibility made it the most widely adopted front-end technology.

Core Concepts
  • Virtual DOM — React maintains an in-memory copy of the DOM and computes minimal updates
  • JSX — JavaScript XML: write HTML-like syntax inside JavaScript
  • Components — functions that return JSX; reusable, composable
  • Props — data passed from parent to child (one-way, read-only)
  • State — useState() hook manages local component data
  • Hooks — useEffect, useContext, useRef and more
  • One-way data flow — data flows down; events bubble up
Key Facts
LanguageJavaScript / TypeScript
ArchitectureComponent-based, one-way binding
RenderingVirtual DOM diffing
Learning curveModerate (JSX takes getting used to)
Used byFacebook, Instagram, WhatsApp, Netflix
EcosystemNext.js, Redux, React Router, React Native
StudentCard.jsx — React component example
// React functional component (modern style)
import { useState } from 'react';

// Component = a function that returns JSX
function StudentCard({ name, course, gpa }) {

  // useState hook — local state
  const [isVisible, setIsVisible] = useState(true);

  // JSX — looks like HTML inside JavaScript
  return (
    <div className="card">
      <h3>{name}</h3>                    // {} = JS expression
      <p>Course: {course}</p>
      {isVisible && <p>GPA: {gpa}</p>}    // conditional render
      <button onClick={() => setIsVisible(!isVisible)}>
        {isVisible ? 'Hide GPA' : 'Show GPA'}
      </button>
    </div>
  );
}

// Using the component — props passed like HTML attributes
<StudentCard name="Arjun" course="MCA" gpa={8.7} />
Virtual DOM explained: When state changes, React creates a new Virtual DOM tree, diffs it against the previous one (reconciliation), and applies only the changed parts to the real DOM. This avoids expensive full re-renders. jQuery would update the whole DOM; React updates only exactly what changed.

Framework Overview
Angular — Full Framework by Google
🅰
Angular
Complete rewrite of AngularJS by Google (2016)  ·  Written in TypeScript Full framework Enterprise choice

Angular is a complete, opinionated framework — it includes everything: routing, HTTP client, forms, animations, testing, and CLI tools. It uses TypeScript by default and enforces a strict project structure. Preferred in large enterprise applications where conventions and consistency matter more than flexibility.

Core Concepts
  • Components — TypeScript class + HTML template + CSS
  • Modules (NgModule) — group related components and services
  • Templates — HTML with Angular directives and binding syntax
  • Data binding — one-way [property], event (event), two-way [(ngModel)]
  • Dependency Injection — services injected into components automatically
  • Decorators — @Component, @Injectable, @NgModule
  • Change detection — Zone.js tracks async changes automatically
Key Facts
LanguageTypeScript (mandatory)
ArchitectureMVC / Component-based
Data bindingTwo-way (via ngModel)
Learning curveSteep (TypeScript + Angular concepts)
Used byGoogle, Microsoft, Forbes, Samsung
EcosystemAngular CLI, RxJS, Angular Material
student-card.component.ts — Angular component
// Angular component — TypeScript decorator + class
import { Component, Input } from '@angular/core';

@Component({
  selector:    'app-student-card',    // HTML tag name
  templateUrl: './student-card.html',
  styleUrls:   ['./student-card.css']
})
export class StudentCardComponent {
  @Input() name:   string = '';  // receives data from parent
  @Input() course: string = '';
  @Input() gpa:    number = 0;

  isVisible = true;

  toggleGPA() {
    this.isVisible = !this.isVisible;
  }
}

// student-card.html template
<div class="card">
  <h3>{{ name }}</h3>               <!-- interpolation -->
  <p>Course: {{ course }}</p>
  <p *ngIf="isVisible">GPA: {{ gpa }}</p> <!-- directive -->
  <button (click)="toggleGPA()">    <!-- event binding -->
    {{ isVisible ? 'Hide' : 'Show' }} GPA
  </button>
</div>

Framework Overview
Vue.js — Progressive Framework
🟢
Vue.js
Created by Evan You (ex-Google, 2014)  ·  Community-maintained Progressive framework Easiest to learn

Vue is called "progressive" because you can adopt it incrementally — use just the core view layer for a small project, or add Vue Router, Pinia, and Nuxt for a full-scale app. It combines React's component model with AngularJS's template directives into a gentler learning curve.

Core Concepts
  • Single File Components (.vue) — template, script, and style in one file
  • Reactive data — ref() and reactive() make variables reactive
  • Directives — v-if, v-for, v-bind, v-on, v-model
  • Two-way binding — v-model binds input to data automatically
  • Computed properties — cached derived values based on reactive data
  • Composition API — modern Vue 3 way (similar to React hooks)
  • Props and Emits — parent-child communication
Key Facts
LanguageJavaScript or TypeScript
ArchitectureMVVM / Component-based
Data bindingReactive (two-way via v-model)
Learning curveLow — gentlest of the three
Used byAlibaba, Xiaomi, GitLab, Nintendo
EcosystemNuxt.js, Pinia, Vue Router, Vite
StudentCard.vue — Vue Single File Component
<!-- Vue Single File Component (.vue) -->
<!-- Three sections: template + script + style -->

<template>
  <div class="card">
    <h3>{{ name }}</h3>               <!-- interpolation -->
    <p>Course: {{ course }}</p>
    <p v-if="isVisible">GPA: {{ gpa }}</p>  <!-- directive -->
    <button @click="toggleGPA">         <!-- event -->
      {{ isVisible ? 'Hide' : 'Show' }} GPA
    </button>
  </div>
</template>

<script setup>        // Composition API (Vue 3)
import { ref, defineProps } from 'vue';

const props = defineProps(['name', 'course', 'gpa']);
const isVisible = ref(true);   // reactive variable

function toggleGPA() {
  isVisible.value = !isVisible.value;
}
</script>

<style scoped>        /* scoped = styles apply only to this component */
.card { padding: 1rem; border-radius: 8px; }
</style>

VTU Core Topic — AngularJS
AngularJS (Angular 1) — Deep Dive
AngularJS is Angular 1, written in plain JavaScript (not TypeScript). It was the first major front-end MVC framework and is the subject specified in your VTU syllabus. Note it is different from modern Angular 2+.
Important: Your textbook references AngularJS by Krishna Rungta which covers Angular 1 (AngularJS). AngularJS ≠ Angular. AngularJS (2010) uses JavaScript and the MVC pattern with controllers and $scope. Angular 2+ (2016) uses TypeScript and a completely different architecture.
How AngularJS works

AngularJS extends HTML with special attributes (directives). You link a JavaScript controller to an HTML section. The controller exposes a $scope object. Every property on $scope automatically appears in the HTML, and vice versa.

Minimal AngularJS setup
<!-- Step 1: load AngularJS -->
<script src="angular.min.js"></script>

<!-- Step 2: ng-app marks the Angular boundary -->
<div ng-app="myApp"
     ng-controller="MyCtrl">
  <input ng-model="name">
  <p>Hello, {{ name }}!</p>
</div>

// Step 3: create the app and controller
var app = angular.module('myApp', []);

app.controller('MyCtrl', function($scope) {
  $scope.name = 'VTU Student';
});

A controller is a JavaScript function that sets up the $scope — the shared data model between the HTML and the JavaScript logic.

controllers.js — complete controller example
var app = angular.module('studentApp', []);

// Controller — exposes data and functions via $scope
app.controller('StudentCtrl', function($scope) {

  // Data on $scope is available in HTML
  $scope.students = [
    { name: 'Arjun',  course: 'MCA', gpa: 8.7 },
    { name: 'Priya',  course: 'MCA', gpa: 9.1 },
    { name: 'Ravi',   course: 'BCA', gpa: 7.8 },
  ];

  $scope.newStudent = { name: '', course: '', gpa: 0 };

  // Functions on $scope are callable from HTML
  $scope.addStudent = function() {
    if ($scope.newStudent.name) {
      $scope.students.push({...$scope.newStudent});
      $scope.newStudent = {};  // clear form
    }
  };

  $scope.removeStudent = function(index) {
    $scope.students.splice(index, 1);
  };

  $scope.getAvgGPA = function() {
    const total = $scope.students.reduce(
      (s, st) => s + st.gpa, 0
    );
    return (total / $scope.students.length).toFixed(2);
  };
});
Two-Way Data Binding

AngularJS's most celebrated feature. The HTML and JavaScript model stay in sync automatically. Change the input — the variable updates. Change the variable — the HTML updates. No event listeners needed.

two-way-binding.html
<div ng-app="app"
     ng-controller="Ctrl">

  <!-- ng-model creates two-way binding -->
  <input ng-model="username"
         placeholder="Enter name">

  <!-- Automatically shows updated value -->
  <p>Hello, {{ username }}!</p>

  <!-- Also works on select and checkbox -->
  <input type="checkbox"
         ng-model="agreed"> Agree
  <p>Agreed: {{ agreed }}</p>
</div>

How it works internally: AngularJS uses a digest cycle — it watches all $scope variables in a loop. When any value changes, it re-evaluates all watchers and updates the DOM. This is called dirty checking.
Filters — format output in templates

Filters format the value of an expression for display using the pipe | character.

filters.html
<!-- Built-in filters -->
{{ name | uppercase }}
{{ name | lowercase }}
{{ gpa  | number:2 }}      2 decimal places
{{ fee  | currency:"₹" }}  currency symbol
{{ date | date:'dd/MM/yy'}}format date

<!-- filter on ng-repeat -->
<li ng-repeat="s in students
           | filter:searchText
           | orderBy:'name'">
  {{ s.name }}
</li>

// Custom filter in JS
app.filter('grade', function() {
  return function(score) {
    return score >= 75 ? 'A' : 'B';
  };
});
Services — reusable singletons

Services hold shared logic or data. AngularJS has built-in services (prefixed with $). You can create custom ones.

services.js
// Built-in services
// $http — AJAX requests
app.controller('Ctrl',
  function($scope, $http) {

  $http.get('/api/students')
    .then(function(res) {
      $scope.students = res.data;
    });
});

// Custom service
app.service('StudentService',
  function() {
    this.getGrade = function(gpa) {
      return gpa >= 8 ? 'A' : 'B';
    };
});

// Inject into controller
app.controller('Ctrl',
  function($scope, StudentService) {
    $scope.grade =
      StudentService.getGrade(8.7);
});

student-app.html — complete AngularJS application
<!DOCTYPE html>
<html ng-app="studentApp">   <!-- ng-app bootstraps Angular -->
<head>
  <script src="https://ajax.googleapis.com/ajax/libs/angularjs/1.8.3/angular.min.js"></script>
</head>
<body ng-controller="StudentCtrl">

  <h2>VTU Student List</h2>

  <!-- Search filter -->
  <input ng-model="searchText" placeholder="Search students...">

  <!-- ng-repeat with filter and orderBy -->
  <table>
    <tr ng-repeat="student in students | filter:searchText | orderBy:'name'">
      <td>{{ student.name }}</td>
      <td>{{ student.gpa | number:1 }}</td>      <!-- filter -->
      <td>{{ student.gpa | grade }}</td>          <!-- custom filter -->
      <td>
        <button ng-click="remove($index)">Remove</button>
      </td>
    </tr>
  </table>

  <!-- Add form -->
  <form ng-submit="add()">
    <input ng-model="newName"  placeholder="Name">
    <input ng-model="newGpa"   placeholder="GPA"  type="number">
    <button type="submit">Add Student</button>
  </form>

  <p>Total: {{ students.length }} | Avg GPA: {{ avgGPA() }}</p>

var app = angular.module('studentApp', []);

// Custom filter
app.filter('grade', function() {
  return function(gpa) {
    return gpa >= 9 ? 'A+' : gpa >= 8 ? 'A' :
           gpa >= 7 ? 'B'  : 'C';

app.controller('StudentCtrl', function($scope) {

Architecture Pattern
MVC and MVVM Patterns in Front-End Frameworks
Understanding the architectural patterns that frameworks implement helps you understand how data flows through the application.
M — Model
The data and business logic. In AngularJS: the $scope object and services. In React: state and props. In Vue: reactive data. The Model knows nothing about the UI.
V — View
The HTML template that the user sees. In AngularJS: HTML with directives. In React: JSX returned from a component. In Vue: the <template> section. The View displays data, fires events.
C/VM — Controller/ViewModel
Mediates between Model and View. MVC uses a Controller (AngularJS). MVVM uses a ViewModel that is auto-synced via data binding (Vue, Angular). React uses component functions as the mediator.

User types in input → ng-model updates $scope → Controller logic runs → $scope data updates → View re-renders automatically (digest cycle)
MVVM (Model–View–ViewModel): Used by Vue and Angular 2+. The ViewModel is automatically synchronised with the View through data binding — you don't manually update the DOM. AngularJS is technically an MVC framework, but its two-way binding gives it MVVM-like behaviour, which is why it's often called MV* (Model-View-Whatever).

VTU Quick Reference — AngularJS Directives
ng-appBootstraps the AngularJS application. Must be on the root HTML element.
ng-controllerBinds a controller function to an HTML section. The controller manages $scope for that section.
ng-modelTwo-way binds an input/select/textarea to a $scope variable. Changes in either direction propagate automatically.
ng-repeatRepeats an element for each item in an array. Use $index for position. Supports filter and orderBy.
ng-ifAdds or removes element from DOM based on condition. ng-show/ng-hide keep element in DOM but toggle visibility.
ng-clickBinds a click handler. Calls a $scope function. e.g. ng-click="save()"
{{ expression }}Interpolation — displays the value of a $scope expression. Updates automatically when data changes.
$scopeThe glue between controller and view. All data and functions attached to $scope are accessible in the template.
$httpBuilt-in service for AJAX calls. $http.get(url).then(fn). Angular-aware — triggers digest after response.
filter | orderByBuilt-in filters for ng-repeat. filter:searchText narrows results. orderBy:'field' sorts the array.
Dependency InjectionServices passed as named parameters to controllers. Angular resolves them automatically. e.g. function($scope, $http)
Digest cycleAngularJS's change detection — loops through all watchers, detects changes, and updates DOM. Called dirty checking.
Key VTU exam distinctions to remember: (1) AngularJS ≠ Angular — they are completely different. (2) React is a library, not a full framework. (3) Two-way data binding is a key AngularJS feature — change input, model updates; change model, view updates. (4) ng-repeat is AngularJS's loop directive (React uses .map(), Vue uses v-for). (5) $scope is AngularJS-specific — modern frameworks don't use it.
