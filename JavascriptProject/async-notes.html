Foundation
Synchronous vs Asynchronous
JavaScript is single-threaded — it can only do one thing at a time. Synchronous code runs line-by-line, blocking everything until each line finishes. Asynchronous code lets long tasks (network calls, timers) run in the background so the page stays responsive.
🔴 Synchronous — blocks
// Each line waits for the previous
console.log("Step 1");

// Imagine this takes 3 seconds
const result = heavyTask(); // BLOCKS

console.log("Step 2"); // waits
console.log("Step 3"); // waits

// Page is frozen for 3 seconds!
🟢 Asynchronous — non-blocking
// Long task runs in the background
console.log("Step 1");

setTimeout(() => {
  console.log("Step 2 (after 3s)");
}, 3000); // schedules, doesn't block

console.log("Step 3"); // runs immediately!

// Output: Step 1 → Step 3 → Step 2
The Event Loop: JavaScript uses a call stack for synchronous code and a callback queue for async tasks. The event loop continuously checks — when the call stack is empty, it picks the next task from the queue and runs it. This is why setTimeout(fn, 0) still runs after synchronous code finishes.

02
Async JavaScript
Callbacks
A callback is a function passed as an argument to another function, to be called when an async task completes. It was the original way to handle async JavaScript — still used in many older APIs.
What is a callback?

You pass a function into another function. When the task finishes, it calls back your function with the result.

Think of it like ordering food: you give the waiter your number (the callback). When the food is ready, they call your number — you don't stand at the counter waiting.

⚠ Callback Hell

When callbacks are nested inside callbacks, code becomes deeply indented and hard to read. This is called Callback Hell or the "Pyramid of Doom".

login(user, () => {
  getProfile(user, () => {
    getCourses(user, () => {
      getGrades(user, () => {
        // pyramid of doom!
      });
    });
  });
});

Promises and async/await solve this problem.

callbacks.js — reference
// Basic callback pattern
function fetchData(url, callback) {
  // Simulate async task with setTimeout
  setTimeout(() => {
    const data = { name: "Arjun", course: "MCA" };
    callback(null, data); // null = no error, data = result
  }, 1000);
}

// Call with a callback function
fetchData("api/student", function(error, result) {
  if (error) {
    console.log("Error:", error);
    return;
  }
  console.log("Got data:", result.name, result.course);
});

// Node.js error-first callback convention
// callback(error, result) — null for no error

// Callbacks you already use:
document.getElementById('btn').addEventListener('click', function() {
  // THIS is a callback!
});

[1, 2, 3].forEach(function(n) {
  // Also a callback!
});

03
Async JavaScript
Promises
A Promise is an object that represents a value that will be available in the future. It solves callback hell by letting you chain .then() calls instead of nesting callbacks. Introduced in ES6 (2015).
Pending
Initial state — operation in progress, result not yet known
Fulfilled
Operation succeeded — .then() callback runs with the result
Rejected
Operation failed — .catch() callback runs with the error
Creating a Promise
// new Promise takes an executor function
const myPromise = new Promise((resolve, reject) => {
  // Do async work here
  const success = true;

  if (success) {
    resolve("Data loaded!"); // → .then()
  } else {
    reject("Something failed"); // → .catch()
  }
});

// Consume the promise
myPromise
  .then(result => console.log(result))
  .catch(error => console.log(error))
  .finally(() => console.log("Always runs"));
Promise Chaining — vs Callback Hell
// Flat chain — much cleaner than nesting!
login(user)
  .then(token => getProfile(token))
  .then(profile => getCourses(profile.id))
  .then(courses => {
    console.log("Courses:", courses);
  })
  .catch(err => {
    // ONE catch handles ALL errors above
    console.log("Error:", err);
  });

// Promise.all — run multiple in parallel
Promise.all([getUser(), getCourses()])
  .then(([user, courses]) => {
    console.log(user, courses);
  });
Promise.all vs Promise.race: Promise.all([p1, p2, p3]) waits for ALL promises to resolve (fails if any one fails). Promise.race([p1, p2, p3]) resolves/rejects as soon as the FIRST promise settles. Use Promise.allSettled() to get results of all, regardless of success or failure.

04
Async JavaScript
async / await
async/await is syntactic sugar built on top of Promises. It lets you write asynchronous code that looks and reads like synchronous code — no more chaining. Introduced in ES2017. It is the modern standard.
Rules
KeywordWhat it does
async Marks a function as asynchronous. Always returns a Promise, even if you return a plain value.
await Pauses the async function until the Promise resolves. Can ONLY be used inside an async function.
try/catchHandles errors from awaited calls — replaces .catch()
Promise chain → async/await comparison
// Promise chain (old way)
getUser()
  .then(u => getCourses(u.id))
  .then(c => console.log(c))
  .catch(e => console.log(e));

// async/await (modern way — same result!)
async function loadData() {
  try {
    const user    = await getUser();
    const courses = await getCourses(user.id);
    console.log(courses);
  } catch (error) {
    console.log(error);
  }
}
loadData();
Common mistake: await can only be used inside an async function. Using it at the top level of a script (outside any function) causes a SyntaxError in older environments. In modern browsers and Node.js 14+, top-level await is supported in ES modules.

05
Network Requests
AJAX — Asynchronous JavaScript and XML
AJAX is a technique for sending HTTP requests from JavaScript without reloading the page. The original approach used XMLHttpRequest (XHR). Today, the Fetch API replaces it — but you will see XHR in older codebases.
What AJAX enables
Without AJAXWith AJAX
Submit form → full page reloadSubmit form → update just the result area
Load new data → reload pageLoad data → inject into page silently
Search → new page for each querySearch → live results as you type
Every action = server round-trip visible to userBackground requests, seamless UX
XMLHttpRequest (XHR) — the original
// Still used in legacy code
const xhr = new XMLHttpRequest();

xhr.open('GET', 'https://api.example.com/data');

xhr.onload = function() {
  if (xhr.status === 200) {
    const data = JSON.parse(xhr.responseText);
    console.log(data);
  }
};

xhr.onerror = function() {
  console.log('Request failed');
};

xhr.send(); // send the request

// Fetch API is much cleaner — see §6
Why "XML" in AJAX? When AJAX was invented (early 2000s), XML was the standard data format. Today, JSON is used almost exclusively — but the name AJAX stuck. Modern AJAX = JSON over HTTP using the Fetch API or axios.
06
Network Requests
Fetch API
The fetch() function is the modern, Promise-based replacement for XMLHttpRequest. It is built into all modern browsers — no library needed. You pass a URL, get a Promise back, then read the response.
fetch-api.js — complete reference
// ── Basic GET request ─────────────────────────────────────
fetch('https://jsonplaceholder.typicode.com/users/1')
  .then(response => response.json())  // parse JSON body
  .then(data    => console.log(data))
  .catch(error  => console.log('Error:', error));

// ── Same request with async/await ────────────────────────
async function getUser() {
  try {
    const response = await fetch('https://jsonplaceholder.typicode.com/users/1');

    if (!response.ok) {  // ok = true when status 200–299
      throw new Error('HTTP Error: ' + response.status);
    }

    const user = await response.json();
    console.log(user.name, user.email);
  } catch (error) {
    console.log('Failed:', error.message);
  }
}

// ── POST request (send data) ─────────────────────────────
async function createUser(userData) {
  const response = await fetch('https://jsonplaceholder.typicode.com/users', {
    method:  'POST',
    headers: { 'Content-Type': 'application/json' },
    body:    JSON.stringify(userData) // object → JSON string
  });
  return await response.json();
}

// ── Response methods ─────────────────────────────────────
// response.json()    → parse body as JSON (returns Promise)
// response.text()    → parse body as plain text
// response.blob()    → for images/files
// response.ok        → true if status 200-299
// response.status    → HTTP status code (200, 404, 500...)
// response.headers   → response headers

JavaScript Libraries
jQuery — Introduction
jQuery is a JavaScript library that simplifies DOM manipulation, event handling, animations, and AJAX. Released in 2006, it was the most popular JS library for a decade. The motto: "Write less, do more." Modern browsers have closed the gap, but jQuery is still widely used in legacy projects.
Why jQuery was created
In 2006, browsers had massively different JavaScript behaviour. jQuery smoothed those differences behind one simple API. You wrote jQuery code once — it worked everywhere.
The $ symbol
$ is just jQuery's shorthand. $('#id') is the same as jQuery('#id'). It selects elements using CSS selectors — like querySelector, but returns a jQuery object with extra methods.
Should I use jQuery today?
For new projects: probably not — vanilla JS is powerful enough. For existing codebases: yes, jQuery is often deeply embedded. VTU includes it as it is widely referenced in real-world code.
Vanilla JS vs jQuery — side by side
Vanilla JavaScript
// Select
document.getElementById('btn');
document.querySelector('.card');

// Change text
el.textContent = 'Hello';

// Hide element
el.style.display = 'none';

// Add class
el.classList.add('active');

// Click event
el.addEventListener('click', fn);

// AJAX (Fetch)
fetch(url).then(r => r.json());
jQuery — shorter
// Select
$('#btn');
$('.card');

// Change text
$('#el').text('Hello');

// Hide element
$('#el').hide();

// Add class
$('#el').addClass('active');

// Click event
$('#el').click(fn);

// AJAX
$.ajax({ url: url, success: fn });
